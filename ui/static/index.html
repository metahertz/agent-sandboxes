SSH keys

Claude gets an ssh-agent holding only these keys — never the key files. Changes apply immediately, even to a running session. Git uses them via GIT_SSH_COMMAND; SSH goes through the network allowlist below.

API tokens

Claude sees a placeholder in the environment variable; nono's proxy swaps in the real token only on requests to that service. Restart Claude to apply.

Network

Outbound traffic from Claude and everything it runs passes through nono's filtering proxy. Restart Claude to apply.

Resource limits

Applied to Claude's whole process tree via cgroups. Leave empty for no limit. Restart Claude to apply.

Remote terminal (SSH)

Keys added here log in to this workspace only: its Claude session, or a shell and file transfer inside the same nono sandbox as Claude. They apply immediately. Use a key that isn't already allowed to log in to this host.


          

          

            
Always enforced

            
    
              
  • Files: read/write the project folder only (plus Claude's own state); ~/.ssh, credentials, keyrings, browser data and shell history denied.
    • 
              
  • Unix sockets denied by default: no Docker, tmux, D-Bus or systemd --user.
    • 
              
  • Localhost: only this workspace's sandbox port , plus Alloy's telemetry receiver (4318) when Claude Code telemetry is on.
    • 
              
  • Secrets in the pool and other workspaces' keys are never readable inside the sandbox.

Import

        
Uploads land in ~/agent-sandboxes/inbox/<folder>/. Importing moves one into a new workspace and installs its Claude history.

      


      

        

          
Inbox

            

          

        


        

          
Send a project from another machine

          
    
            
  1. On that machine, get export-claude-project (python3 and rsync; Linux or macOS).
    2. 
            
  2. Make a key there for uploads (ssh-keygen -t ed25519 -f ~/.ssh/sandboxes-upload) and add its .pub under Upload keys below. It can only rsync into the inbox.
    3. 
            
  3. Run it from the project folder:
    4. 
          

          

          
It sends the folder (with .git, .claude/, CLAUDE.md; not node_modules, .venv, __pycache__) plus the project's Claude Code sessions, auto-memory, file checkpoints and prompt history. Re-running it resumes. With a normal login instead, use --to user@host:agent-sandboxes/inbox, or --out DIR and copy the folder into the inbox yourself. A plain folder with no history works too.

Monitoring

            Open dashboards ↗

          
Alloy on this host collects workspace, container and host metrics, nono's network log, container logs and the journal, and sends them to Prometheus and Loki.

Import the dashboards from monitoring/grafana/dashboards/ into your Grafana, with datasource UIDs prometheus and loki. Switching to external removes the local containers; their data volumes are kept.
