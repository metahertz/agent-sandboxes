SSH keys

Claude gets an ssh-agent holding only these keys — never the key files. Changes apply immediately, even to a running session. Git uses them via GIT_SSH_COMMAND; SSH goes through the network allowlist below.

API tokens

Claude sees a placeholder in the environment variable; nono's proxy swaps in the real token only on requests to that service. Restart Claude to apply.

Network

Outbound traffic from Claude and everything it runs passes through nono's filtering proxy. An allowed host is reachable on any port, unless you list it with ports: then only those (port changes apply at once, the rest when Claude restarts). Programs that ignore HTTPS_PROXY (database clients, for example) can't connect; SSH and git are set up to use it. Restart Claude to apply.

nono can't limit which address a server binds, so one on 0.0.0.0 is reachable from your network unless the host's firewall blocks it. Ports this app uses (6101–6199, 7100–7199, 8101–8199, 9101–9199, 3128, 4318) and other workspaces' listen ports are refused.

Container network (the sandbox's browser, VS Code and terminal)

“Same as Claude” puts the container on a network with no route out; its browser and shell tools use the proxy, and the rest (DNS, raw TCP) can't connect. Allowlist changes apply to the container at once; switching this, or changing its tokens, recreates the container (its browser session restarts). VS Code extensions need open-vsx.org allowed.

This VM has no network interface: everything in it (Claude, apt, Docker, git over ssh) goes through its proxy on the host, with this allowlist, which applies at once. claude.ai and downloads.claude.ai are always allowed, for installing Claude Code in the VM. Token changes apply when the VM restarts.

Apple builds

Each job is a commit of the project's git repository, pushed by this host to the build host and run by a Mac worker in a fresh macOS VM that's deleted afterwards. The agent gets MCP tools only, never a key or a connection to the build host or the Mac. Set up the build host and workers under Settings → Apple builds. Restart the agent to apply.

Browser container

The same container as a sandbox workspace's, inside the VM: its network is the VM's (this allowlist, through the proxy), and the Browser, VS Code, Terminal and Files tabs reach it over vsock. Its image (about 13 GB) is copied from this host into the VM's disk on the first start, which takes a few minutes; the VM's memory default goes up to the container's memory plus 3G (5G) and its disk to 48G (sparse). Restart the VM to apply.

Resource limits

Applied to Claude's whole process tree via cgroups (CPUs as a CPU quota: 2 = two cores' worth). Leave empty for no limit. Restart Claude to apply.

The VM's size. Empty means the default: 2G of memory (with the browser container, its memory plus 3G), 2 vCPUs, and a 16G disk (48G with the browser container). The disk is sparse, so it only takes the space the VM writes, and it can grow but never shrink. Restart the VM (Stop, then Start) to apply.

Browser container

The AIO container's memory (Chromium's shared memory is the same size, inside it) and CPUs. Empty means 2G and 2 CPUs. Saving a change recreates a running container, so its browser session restarts.Only used with the browser container ticked; at most the VM's vCPUs, and the VM needs 1G more memory than the container. Restart the VM to apply.

Hermes model

Hermes' model provider, pinned over its own config.yaml (managed settings). With an API key, the key goes in the pool and Hermes gets only a placeholder: the proxy adds the real key on requests to that provider (an http:// server on your network goes through the bridge, so it needn't be on the allowlist). A server that needs no key must be let through the network allowlist (e.g. 192.168.1.20:11434). Restart Hermes (and its gateway) to apply.

Saving adds the key to the pool (Keys & tokens) and ticks it for this workspace.

Chat gateway: who may talk to it

A Telegram, Discord or Slack token ticked above turns that platform on for Hermes' gateway (the tokens stay placeholders; the proxy swaps them in). Hermes answers only these user IDs (comma-separated) and refuses everyone else. Set here, so the agent can't widen it. Restart the gateway to apply.

Google grants appear above like tokens: create them under Keys & tokens. Hermes reads mail as untrusted input, so keep this workspace's network narrow.

Notes for Claude

A marked block at the end of the file, refreshed whenever Claude starts and removed when you untick this; the rest of the file is left alone. It's part of the project, so it shows up in git. Whether or not this is on, Claude is told at startup how to call this workspace's API tokens.

Remote terminal (SSH)

Keys added here log in to this workspace only: its Claude session, or a shell and file transfer inside the same nono sandbox as Claude. They apply immediately. Use a key that isn't already allowed to log in to this host.

    •

    •

    • 
              
  • Secrets in the pool and other workspaces' keys never enter the VM; API tokens are swapped in by the proxy on the host.
    •

    • 
              
  • Unix sockets denied by default: no Docker, tmux, D-Bus or systemd --user.
    • 
              
  • Localhost: only this workspace's sandbox port , plus Alloy's telemetry receiver (4318) when Claude Code telemetry is on, and its listen ports.
    • 
              
  • Secrets in the pool and other workspaces' keys are never readable inside the sandbox.

Set up a Hermes agent

        
A guided first setup: where it runs, its model, who can chat with it, what it may read. Everything here can be changed later in the workspace's Access tab.
